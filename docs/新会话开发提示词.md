【实测结论 · 直接按这些写，别再试错】
- `spark-x2.6` 是纯文本模型、**不支持图片**；拍照必须走 OCR 大模型 `se75ocrbm`（HTTPS POST，`header.app_id` + `parameter.ocr` + `payload.image.image` base64 编码后 ≤4M）。
- OCR 响应 `payload.result.text` **也是 base64**（`compress=gzip` 时先解压），解码后是含 `document[]` + `image[]` 的 JSON；**只取 `document[].value`（markdown）** 喂给 X2.6，别整包塞（实测 6909 字 vs 190 字）。`header.code == 0` 才算成功，`header.sid` 留档排错。
- 两种 OCR 签名 host（`api.xf-yun.com` / `cbm01...`）都返回 `code=0`，默认用与实际请求域名一致的 `cbm01...`，保留 `XFYUN_OCR_SIGN_HOST` 可配置。
- **IPA 音标 OCR 实测 3/3 损坏**（变成 `☐`、`$\square`）。抽取 prompt 必须显式写「忽略 OCR 里的音标，按单词重新生成标准 IPA」，实测能 3/3 补全；再经人工校对页确认。词性可能被污染成 `v.$`，要清洗。
- X2.6 抽取 / 判分在 20s 会超时，客户端超时 ≥60–90s；`temperature: 0.1` 以稳定返回严格 JSON。
- 两套凭据互不通用：MaaS 用 `Bearer ak-...`；OCR / 听写 / 合成共用 APPID + APIKey + APISecret 签名。OpenAI 兼容 `base_url` 只填到 `/v2`。
- 超拟人合成**没有 `language` 参数**，中英靠两个 `vcn` 发音人切换（英文音色授权未验证，不可用就降级原生 TTS）；音频分帧返回且顺序不保证，必须按 `seq` 重排；`speed` 默认是 50 而非 1.0，要做倍数标定。语音听写单次音频 ≤60s，且**只返回文本、没有任何发音评分信息**。
- `result_format` 建议 `json,markdown`，`rotation_min_angle: 5` 可自动旋正拍照。
