# 英语听读软件 — 开发方案（第一版）

> 状态：**方案与文档阶段，尚未创建工程代码**。整理日期：2026-11-06。
> 接口与凭据见 [`讯飞接口配置.md`](讯飞接口配置.md)；项目约定见根目录 `AGENTS.md`。

---

## 1. 产品目标

安卓手机上的英语听读练习工具，uni-app 开发，打包 APK。核心闭环：**把纸质/屏幕上的单词表拍下来变成可练习的词库，再用三种模式反复听、说、被评价**。

## 2. 需求口径

| 编号 | 功能 | 说明 |
|---|---|---|
| 1 | 拍照入库 | 拍照 → 识别成文本 → 筛出**单词、读音、翻译** → 保存到首页。每次拍照生成一个「学习单元」 |
| 2 | 功能选择 | 在首页选中保存的内容后，选择 2.1 / 2.2 / 2.3 |
| 2.1 | 中英共读 | 朗读中文和英文，不作答，按间隔自动进入下一条 |
| 2.2 | 看中说英 | 读中文，用户通过**录音或输入框**给出英文，系统评价 |
| 2.3 | 看英说中 | 读英文，用户通过**录音或输入框**给出中文，系统评价 |
| 3 | 设置 | 全局朗读速度；2.1 配间隔时长；2.2 / 2.3 配「提交后进入下一个」或「间隔一定时间后进入下一个」 |

**口径（2026-11-06 已确认）**

- 用户确认「2.4」是**笔误**，只有 2.1 / 2.2 / 2.3 三种模式，不加第四种。
- 「读音」拆为三件套：IPA 音标 + 发音音频 + 可调速 TTS 朗读。**音标来源已定**：OCR 识别结果实测 3/3 损坏，一律丢弃，由 Spark X2.6 按单词重新生成，经校对页确认。
- 用户确认 2.2 **只做「内容正确度」评价，不做发音评分**（不接 ISE）。2.2 与 2.3 的算法仍有区别：2.2 评英文文本是否答对，2.3 评中文释义是否对（含同义表述），UI 文案不得出现「发音分 / 准确度 / 流利度」。
- 用户**没有服务器**，且明确「这是自己学习用的 app」，已选 **方案 C：APK 完全独立运行**（密钥随包、App 端自行签名直连讯飞，不依赖电脑 / 服务器 / 云账号），授权与落地细则见第 11 节。

## 3. 三种模式与设置矩阵

| | 2.1 中英共读 | 2.2 看中说英 | 2.3 看英说中 |
|---|---|---|---|
| 系统播报 | 英文 → 中文释义 | 中文释义 | 英文单词 / 例句 |
| 用户作答 | 无 | 录音或输入英文 | 录音或输入中文 |
| 评价 | 不评分 | **内容正确度**（转写文本比对 + Spark X2.6 判分；无发音分） | 中文转写 + 关键词 / 语义匹配 |
| 推进 | 间隔 N 秒后自动下一条 | 提交后 / 定时 | 提交后 / 定时 |

| 设置项 | 适用 | 取值 / 默认 |
|---|---|---|
| 朗读速度 | 全局 | 0.5×–2.0× / 1.0× |
| 英美发音、音量、自动播放 | 全局 | US / UK |
| 播放顺序、重复次数 | 2.1 | 英→中、中→英、仅英；1–3 次 |
| **条目间隔时长** | 2.1 | 0–10 s / 1.5 s |
| 作答方式 | 2.2 / 2.3 | 录音 / 输入框 |
| **推进模式** | 2.2 / 2.3 | 提交后 / 定时；默认提交后 |
| 等待秒数 | 2.2 / 2.3 定时模式 | 1–15 s / 3 s |
| 评分严格度 | 2.2 / 2.3 | 宽松 / 标准 / 严格 |

练习页用状态机 `idle → playing → awaiting → evaluating → advancing` 管理，避免定时推进与用户作答冲突；播放队列用「播放完成回调」驱动，不用固定 sleep。

## 4. 技术架构

| 层 | 选型 |
|---|---|
| 框架 | uni-app（Vue3 + Vite + TypeScript），App-Plus 打 Android APK。一期不上 uni-app x |
| 本地库 | `plus.sqlite`（SQLite），设置可用 `uni.setStorage` |
| 界面层 | 首页 / 拍照 / 识别校对 / 功能选择 / 练习 / 结果 / 设置 / 错词本 |
| 能力层（可插拔） | OCR、结构化抽取、TTS、ASR、评测。上层只依赖接口，不感知底层是讯飞云还是安卓原生 |
| 数据层 | 词条库、设置、练习记录、音频缓存；离线可用 |
| 云能力 | **第一版统一用讯飞**：Spark X2.6、通用文档识别（OCR大模型）、语音听写 V2.0、超拟人合成。见接口配置文档 |
| 网络与凭据（方案 C） | **无后端、无代理层**：HMAC-SHA256 签名在 App 端完成，`uni.request` / `uni.connectSocket` 直连讯飞。App 端走原生网络栈不受 CORS 限制；密钥构建期注入产物，源码仓库不含密钥 |

界面层、能力层、数据层三层分离；云能力按需联网，本地数据与播放控制始终可用。能力层做成可插拔是硬要求——第一版**明确不接 ISE**，英文 TTS 音色授权未定（可能降级安卓原生 TTS），ASR 也要保留无网输入框降级，且**日后若要分发/上架需从方案 C 迁到云函数**；换实现时不允许改 UI，只改 `src/api/`。

## 5. 第一版能力映射（讯飞）

| 模块 | 第一版实现 | 状态 |
|---|---|---|
| 拍照 OCR | 讯飞**通用文档识别（OCR大模型）** `se75ocrbm`，HTTPS POST，输出 `document[].markdown` | **已联调通过**（两种签名 host 均 `code=0`） |
| 结构化抽取 | Spark X2.6，把 OCR 的 **markdown 文本**（不是整包 JSON）整理成严格词条 JSON → 人工校对页 | 已端到端验证 |
| 词条音标补全 | **必需步骤**：丢弃 OCR 音标，Spark X2.6 按单词重新生成 IPA + 人工确认 | 已实测 3/3 正确补全 |
| 中文 / 英文朗读 | 讯飞超拟人合成（WebSocket），中文与英文用**两个不同 vcn 发音人**，`speed` 映射朗读速度，音频本地缓存 | 握手 101 通过；英文音色授权未验证，不可用则英文降级为安卓原生 TTS |
| 录音转写 | 讯飞语音听写大模型（中英）V2.0，16k 单声道，≤60s | 握手 101 通过，业务帧待 P4 |
| 2.2 评价 | **内容正确度**：ASR 转写文本比对 + Spark X2.6 语义判分，**不接 ISE、不给发音分** | 用户已定 |
| 2.3 中文判分 | 听写转写 + 关键词覆盖，Spark X2.6 兜底语义相似度 | 可用 |
| 输入框作答 | 跳过 ASR，直接做文本比对 / 语义判分 | 可用 |

**拍照链路（已确定为两段式）**

```
拍照 → 图片压缩(≤4M base64) → OCR大模型 se75ocrbm（App 端签名、直连）
     → payload.result.text 是 base64，解码后是一个含 document[] + image[] 的 JSON
     → 只取 document[].value（markdown），丢掉版面坐标
     → Spark X2.6 抽取词条 JSON（**忽略并重新生成音标**）→ 人工校对页 → 本地入库
```

`spark-x2.6` 是纯文本推理模型，**不支持图片输入**，所以 OCR 必须走独立接口。OCR 与听写、合成共用同一组 APPID / APIKey / APISecret 签名三元组。

**2026-11-06 已联调**：两种签名 host 都返回 `code=0`，401 疑虑排除；一张三行单词表实测中英文单词与中文释义全对、词性轻微污染、**IPA 音标 3/3 损坏**，改由模型按单词重生成后 3/3 正确。完整实测记录见 `讯飞接口配置.md` 第 8 节——这是 P2 抽取 prompt 与校对页设计的直接依据。

### 关于安卓原生能力（已核实结论）

- **TTS 原生可用**：`plus.android.importClass('android.speech.tts.TextToSpeech')` + `plus.android.implements('...TextToSpeech$OnInitListener')`，`setLanguage` / `setSpeechRate` / `speak` 即可，完全离线、免费。风险是中文语音包可能 `LANG_MISSING_DATA`。
- **ASR 原生不可作为唯一依赖**：国内无 GMS 的 ROM 上 `SpeechRecognizer.isRecognitionAvailable()` 常返回 false；即便探测到 OEM 引擎，也只返回纯文本、弹系统 UI、无音素与置信度，做不了发音评分。
- 第一版既然已选定讯飞，原生 TTS / ASR 就作为**无网降级档**保留在能力层接口后面，不进主线。

### 三档配置（保留扩展性）

| 档位 | TTS | ASR | 2.2 评价 | 成本 |
|---|---|---|---|---|
| A 纯原生（无网降级） | 系统 TTS | 系统 SpeechRecognizer + OEM 探测，失败转输入框 | 仅文本准确率 | 0 |
| **B 讯飞（第一版，已定）** | 超拟人合成 | 语音听写大模型 V2.0 | **内容正确度**，不接 ISE | 按量 |
| C 全能力（日后可选） | 同 B | 同 B | 补讯飞语音评测 ISE，升级为发音评分 | 按量，更高 |

用户已选 B 档的「内容正确度」口径；C 档仅是能力层预留的升级路径，不在第一版范围。

## 8. 安全与架构红线（方案 C）

1. **源码仓库不含密钥**：MaaS `ak-` Key 与私有接口三元组只从本地 `.env.local`（已 gitignore）在构建期注入，代码里只出现环境变量名。密钥**只存在于产物 APK** —— 这是用户 2026-11-06 明确授权的例外（「这是我自己学习用的 app，场景选 C」）。
2. **补偿措施，缺一不可**：密钥分片 + 运行时拼接或放 native 层，禁止明文整串；构建开启代码混淆、打包后做一次免费加固；讯飞控制台设用量上限与告警；APK 只装自己手机、不外传不上架；异常用量立即轮换。
3. 日志禁止打印密钥、签名串、完整鉴权 URL（含查询参数）、请求体中的 `app_id` 与图片 base64 —— **App 运行时同样禁止**。
4. 讯飞返回的合成音频、识别文本按最小必要缓存，遵守隐私政策说明（相机、麦克风、第三方 AI 服务）。
5. 签名依赖 GMT RFC1123 时间，容差 ±300s；**手机系统时间不准会 401**，要检测并提示校准，且不要缓存签名 URL（现用现签）。
6. **无代理层**：App 端 `uni.request` / `uni.connectSocket` 直连讯飞，不依赖电脑 / 服务器 / 云函数。OCR 文档里「不支持跨域、不适用于浏览器」只约束 H5；App 端走原生网络栈，不受 CORS 限制。
7. **分发即迁移**：一旦要给别人用、多人使用或上架，必须先切到云函数方案（第 11 节 B），不得沿用 C 发布。

3. 真实拍照素材的 OCR 表现（倾斜 / 光照 / 手写 / 多栏）—— P2 用实拍图验证，本次只用电脑生成的清晰图。

### 10.3 已澄清、不再存疑

`spark-x2.6` 不支持图片输入 · OCR 响应 `text` 是 base64 且解码后为含 `document[]`/`image[]` 的 JSON · 两种 OCR 签名 host 都通过 · 四个接口鉴权全绿 · OCR 音标必然损坏、由 X2.6 重生成 · 安卓原生 TTS 可用而 ASR 不能作主力 · 超拟人英文靠 vcn 切换 · 两套鉴权体系不能混用。

## 11. 独立运行方案 C（已定，2026-11-06）

### 11.1 授权与结论

用户明确：「**这是我自己学习用的 app，场景选 C**」，即接受「APK 可被反编译、密钥可能被提取」的风险。

**结论：APK 完全独立运行。** 不需要电脑常开、不需要服务器、不需要云账号、不需要同一 WiFi。手机装好、联网即可使用全部功能；断网时首页、词条与已缓存音频仍可用。

`AGENTS.md` 第 4 节据此对「签名必须服务端完成」开了**自用例外**，同时把补偿措施列为必做项；该授权**仅限自用**，一旦要分发 / 上架 / 多人使用，必须先迁到 11.5 的 B 方案。

### 11.2 为什么可行（技术核查）

- 之前写的「OCR 不支持跨域、不适用于浏览器 → 必须代理」，**这条只约束 H5 / 浏览器**。uni-app **App 端 `uni.request` 走原生网络栈，没有同源策略，不受 CORS 限制**；`uni.connectSocket` 直连 WSS 同理。
- HMAC-SHA256 签名只是标准算法（`host / date / request-line` + APIKey + APISecret），不依赖任何服务端能力。`tools/proxy.py` 的 `auth_query()` 已实测能签出有效 URL（四个接口鉴权全通过），把它翻译成 App 端 TypeScript 即可，逻辑等价。
- 因此**「开电脑」从来不是技术必需**，只是「把密钥放在电脑上」那个方案的副作用。C 方案下这层依赖整个消失。

### 11.3 工程落地（P1 一并做）

| 项 | 做法 |
|---|---|
| 签名模块 | `src/api/xfyun-sign.ts`：GMT RFC1123 `date` → HMAC-SHA256 → base64 → `authorization` → 拼 URL。WSS 请求行用 `GET`，OCR 用 `POST`；**现用现签，不缓存签名 URL** |
| 依赖 | 轻量 crypto（`@noble/hashes` / `crypto-js`）+ base64；**不引原生插件、不需要自定义基座**，云打包即可 |
| 密钥注入 | 构建期从 `.env.local` 经 Vite 注入；源码仓库只有键名。运行时由分片常量拼接，避免整串明文 |
| 网络 | `uni.request`（MaaS / OCR）、`uni.connectSocket`（听写 / 合成）；超时 OCR 30s、MaaS 90s；统一 429 退避重试 |
| 设备时间 | 启动或首次 401 时检测本机与 GMT 偏差，>120s 提示校准（服务端容差 ±300s） |
| 日志 | 统一请求拦截器脱敏，禁止输出 `Authorization`、签名串、完整鉴权 URL、`app_id`、图片 base64 |
| 打包 | 开启代码混淆；产出 APK 后做一次免费加固；讯飞控制台设用量上限与告警 |

### 11.4 风险与补偿措施（必须全做）

| 风险 | 措施 |
|---|---|
| 反编译直接读到密钥明文 | 分片拼接 / native 层存放 + 代码混淆 + 免费加固 |
| 密钥被盗刷产生费用 | 控制台**用量上限 + 告警**；异常立即轮换（只改 `.env.local` 重新打包） |
| 日志 / 崩溃上报泄露 | 日志脱敏；不接第三方崩溃收集 |
| APK 落到别人手里 | **只装自己手机，不外传、不上架、不分发** |
| 手机时间不准导致 401 | 11.3 的时间偏差检测与提示 |
| 无网络 | 本地 SQLite + 音频缓存 + 输入框作答降级 |

> **关键边界：密钥进 APK ≠ 密钥进代码仓库。** 仓库里依然一个真实值都没有，泄露仓库不等于泄露密钥；只有 APK 落到别人手里才触发风险。这条边界必须守住，`AGENTS.md` 第 4 节第 1、3 条不因 C 而放宽。

### 11.5 未采用的方案（保留作迁移路径）

- **A 本机代理**：`tools/proxy.py` 已实现并自测，仅用于 P0 联调复现签名，**正式 APK 不使用**。
- **B 云函数**：腾讯云 SCF / 阿里云 FC / Cloudflare Workers 等。**分发、上架或多人使用前必须迁到这里**；因能力层可插拔，迁移只改 `src/api/` 的签名来源与 base URL，UI 不动。
- **讯飞 SparkChain Android SDK**：官方移动端 SDK，native 层处理鉴权，但要写 uni-app 原生插件 + 自定义基座，OCR 大模型是否有对应 SDK 未确认，改造量大，一期不采用。

| | 密钥安全 | APK 独立 | 依赖电脑 | 本项目 |
|---|---|---|---|---|
| A 本机代理 | 高 | 否 | **要** | 仅联调 |
| B 云函数 | 高 | 是 | 不要 | 日后分发时迁 |
| **C 密钥进 APK** | 较低（自用可接受） | **是** | **不要** | **第一版采用** |

### 11.6 验收

1. 关掉电脑、手机换到另一个网络，拍照入库 + 2.1 共读 + 2.2 / 2.3 作答全流程跑通。
2. 仓库 `git status` 无任何密钥文件；反编译 APK 看不到整串明文密钥。
3. 控制台用量上限与告警已设置；APK 未外传。
