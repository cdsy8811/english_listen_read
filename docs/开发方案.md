# 橙子英语 — 开发方案（第一版）

> 状态：**方案与文档阶段，尚未创建工程代码**。整理日期：2026-11-06。
> 接口与凭据见 [`讯飞接口配置.md`](讯飞接口配置.md)；项目约定见根目录 `AGENTS.md`。

---

## 1. 产品目标

安卓手机上的英语听读练习工具，uni-app 开发，打包 APK。核心闭环：**把纸质/屏幕上的单词表拍下来变成可练习的词库，再用三种模式反复听、说、被评价**。

## 2. 需求口径

| 编号 | 功能 | 说明 |
|---|---|---|
| 1 | 拍照入库 | 拍照 → 识别成文本 → 筛出**单词、读音、翻译** → 保存到「词库」。每次拍照生成一个「学习单元」 |
| 2 | 功能选择 | 首页点选学习单元 → 进入「选择练习模式」页（默认显示该单元全部单词）→ 页底 学习 / 中英 / 英中 分别对应 2.1 / 2.2 / 2.3 |
| 2.1 | 学习（朗读） | 只朗读英文，不作答，按间隔自动进入下一条；要中英共读去设置页把「播放顺序」改成英 → 中 / 中 → 英 |
| 2.2 | 看中说英 | 读中文，用户**只能通过录音**给出英文，系统评价（2026-11-21 起不再提供手工输入，防止输入法辅助作答） |
| 2.3 | 看英说中 | 读英文，用户通过**录音或输入框**给出中文，系统评价 |
| 默写 | 默写 | 只显示中文释义，**不朗读、不录音**，学生用页内**自定义 26 键键盘**输入英文后提交（不调用系统输入法）；按 2.2 的内容正确度评分 |
| 3 | 设置 | 全局朗读速度；2.1 配间隔时长；2.2 / 2.3 配「提交后进入下一个」或「间隔一定时间后进入下一个」 |
| 4 | 跟读 | 手工输入 / 粘贴英文短文并按句呈现（2026-11-21 起取代拍照识别）；整段 / 单句 / **点单词**朗读；逐句录音后转写、与原文逐词对齐评分。独立入口，不是 PracticeMode |

**口径（2026-11-06 已确认）**

- 用户确认「2.4」是**笔误**，只有 2.1 / 2.2 / 2.3 三种 PracticeMode，不加第四种。**2026-11-15 用户要求底部菜单新增「默写」**：只显示中文、不朗读、不录音，输入英文后提交——实现为 **2.2 的「只打字」变体**（路由 `mode=2.2&input=type`），复用内容正确度评价与记录表，状态机与 PracticeMode 枚举不变。
- 「读音」拆为三件套：IPA 音标 + 发音音频 + 可调速 TTS 朗读。**音标来源已定**：OCR 识别结果实测 3/3 损坏，一律丢弃，由 Spark X2.6 按单词重新生成，经校对页确认。
- 用户确认 2.2 **只做「内容正确度」评价，不做发音评分**（不接 ISE）。2.2 与 2.3 的算法仍有区别：2.2 评英文文本是否答对，2.3 评中文释义是否对（含同义表述），UI 文案不得出现「发音分 / 准确度 / 流利度」。
- **2026-11-15 补充**：结果卡里「标准英文 / 标准释义」和「你的作答」两行各带一个回放入口（▶ 播放 / ▶ 播放录音），方便学生把标准发音和自己刚录的音对比。回放走同一个播放队列（返回上级 / 切题立即停）；录音用本次录音的本地临时文件，不下发、不落库，切到下一条即失效。转写失败、没有结果卡时，识别结果框里也保留同样的回放入口。
- **2026-11-21 新增「跟读」**：手工输入 / 粘贴英文短文（不联网），整段 / 单句 / 点单词朗读，逐句录音后按**内容正确度**检查。评分口径与 2.2 一致（不接 ISE、不出「发音分 / 准确度 / 流利度」），`PracticeMode` 仍只有三种；详见第 13 节。同日用户要求把原「拍照识别短文」入口改为「手工添加」，新页 `pages/read/compose` 只填名称与正文即可提交，不再走 OCR。
- **2026-11-21 交互调整（用户指定）**：练习页「提交」按钮移进「你的作答」面板（输入框正下方），底部操作条右侧改为「下一条」（出成绩后才可点，未作答仍走「取消」跳过）；跟读练习页删除底部录音提示文字与「跟读步骤」卡；跟读列表顶部中间新增关键字筛选框（匹配标题或任一句子）。
- **2026-11-21 作答方式调整（用户指定）**：**默写**不再用系统输入法，改为页底固定的自定义 26 键键盘（字母 / 退格 / 空格 / 清空 + 取消 / 上一条 / 下一条），答案框只做展示，避免输入法的 AI / 翻译 / 联想把默写变成抄写；**2.2 看中说英删除手工输入，只保留按住录音**；2.3 看英说中不受限制（仍可系统输入法 + 录音）。键盘实现见 `src/components/DictationKeyboard.vue`。
- 用户**没有服务器**，且明确「这是自己学习用的 app」，已选 **方案 C：APK 完全独立运行**（密钥随包、App 端自行签名直连讯飞，不依赖电脑 / 服务器 / 云账号），授权与落地细则见第 11 节。

## 3. 三种模式与设置矩阵

| | 2.1 学习（朗读） | 2.2 看中说英 | 2.3 看英说中 | 默写（2.2 变体） |
|---|---|---|---|---|
| 系统播报 | 英文（默认只读英文；可切英 → 中 / 中 → 英） | 中文释义 | 英文单词 / 例句 | 无（只显示中文释义） |
| 用户作答 | 无 | **只有录音**（按住说话；不提供输入框） | 录音（按住说话）或输入中文，**两者同时可用** | 页内**自定义 26 键键盘**（不弹系统输入法），输入英文后提交 |
| 评价 | 不评分 | **内容正确度**（转写文本比对 + Spark X2.6 判分；无发音分） | 中文转写 + 关键词 / 语义匹配 | 同 2.2（键盘输入的文本） |
| 推进 | 间隔 N 秒后自动下一条 | 提交后 / 定时 | 提交后 / 定时 | 同 2.2 |

默写的实现口径：入口在「选择练习模式」页底部第 4 项，路由 `mode=2.2&input=type`；不播任何音频，也不申请麦克风权限，状态机仍走 `idle → playing → awaiting → evaluating → advancing`。答案框是纯展示的 `view`，页面不渲染 `input / textarea`，**系统输入法（含 AI、翻译、联想）无法被唤起**；字母键、退格、空格、清空与「取消 / 上一条 / 下一条」都在 `components/DictationKeyboard.vue` 里，提交键仍在作答面板。

| 设置项 | 适用 | 取值 / 默认 |
|---|---|---|
| 朗读速度 | 全局 | 0.5×–2.0× / 1.0× |
| 英美发音、音量、自动播放 | 全局 | US / UK |
| 播放顺序、重复次数 | 2.1 | 仅英（默认）、英→中、中→英；1–3 次 |
| **条目间隔时长** | 2.1 | 0–10 s / 1.5 s |
| 作答方式 | 2.2 / 2.3 | **2.2 只有按住录音**（2026-11-21 起移除手工输入）；**2.3 = 输入框 + 按住录音同时可用**；2.2 / 2.3 的录音条固定在页底，按下变红、松开发送 |
| 随机模式 | 2.2 / 2.3 | 关 / 开（默认关）。开关在「选择练习模式」页单元卡右上角；打开后进入中英 / 英中，词条按 Fisher–Yates 打乱后加载，2.1 共读保持顺序 |
| **推进模式** | 2.2 / 2.3 | 提交后 / 定时；默认提交后 |
| 等待秒数 | 2.2 / 2.3 定时模式 | 1–15 s / 3 s |
| 评分严格度 | 2.2 / 2.3 | 宽松 / 标准 / 严格 |
| 默写的设置 | 默写（2.2 变体） | 沿用 2.2 的随机 / 推进 / 等待秒数 / 评分严格度；不需要麦克风权限 |
| 跟读的朗读 | 跟读 | 沿用全局语速 / 音量 / 英美发音；逐句录音上限 60s，不新增模式设置 |

练习页用状态机 `idle → playing → awaiting → evaluating → advancing` 管理，避免定时推进与用户作答冲突；播放队列用「播放完成回调」驱动，不用固定 sleep。

## 4. 技术架构

| 层 | 选型 |
|---|---|
| 框架 | uni-app（Vue3 + Vite + TypeScript），App-Plus 打 Android APK。一期不上 uni-app x |
| 本地库 | `plus.sqlite`（SQLite），设置可用 `uni.setStorage` |
| 界面层 | 底部导航：首页 / 词库 / 跟读 / 我的（设置、学习记录、关于、退出收进「我的」；词典从首页快捷卡进入）；首页按学习单元进入「选择练习模式」页（默认展示该单元全部单词），页底固定 学习 / 中英 / 英中 / 默写 四个入口；另有拍照 / 识别校对 / 练习 / 结果 / 错词本 |
| 能力层（可插拔） | OCR、结构化抽取、TTS、ASR、评测。上层只依赖接口，不感知底层是讯飞云还是安卓原生 |
| 数据层 | 词条库、设置、练习记录、音频缓存；离线可用 |
| 云能力 | **第一版统一用讯飞**：Spark X2.6、通用文档识别（OCR大模型）、语音听写 V2.0、超拟人合成。见接口配置文档 |
| 网络与凭据（方案 C） | **无后端、无代理层**：HMAC-SHA256 签名在 App 端完成，`uni.request` / `uni.connectSocket` 直连讯飞。App 端走原生网络栈不受 CORS 限制；密钥构建期注入产物，源码仓库不含密钥 |

界面层、能力层、数据层三层分离；云能力按需联网，本地数据与播放控制始终可用。能力层做成可插拔是硬要求——第一版**明确不接 ISE**，英文 TTS 曾因音色授权未定而降级安卓原生 TTS（2026-11-21 已领取 `x5_EnUs_Lila_flow`，主线走讯飞），ASR 也要保留无网输入框降级，且**日后若要分发/上架需从方案 C 迁到云函数**；换实现时不允许改 UI，只改 `src/api/`。

| 拍照 OCR | 讯飞**通用文档识别（OCR大模型）** `se75ocrbm`，HTTPS POST，输出 `document[].markdown` | **已联调通过**（两种签名 host 均 `code=0`） |
| 结构化抽取 | Spark X2.6，把 OCR 的 **markdown 文本**（不是整包 JSON）整理成严格词条 JSON → 人工校对页 | 已端到端验证 |
| 词条音标补全 | **必需步骤**：丢弃 OCR 音标，Spark X2.6 按单词重新生成 IPA + 人工确认 | 已实测 3/3 正确补全 |
| 中文 / 英文朗读 | 讯飞超拟人合成（WebSocket），中文与英文用**两个不同 vcn 发音人**，`speed` 映射朗读速度，音频本地缓存 | **2026-11-21 中英均已授权**：中文 `x5_lingxiaoxuan_flow`，英文 `x5_EnUs_Lila_flow`（美式女声，实测 `code=0`）；英文其他 vcn 仍 `11200`，且只有美式音色，选 UK 英音时走原生 TTS |
| 录音转写 | 讯飞语音听写（经典流式版）V2.0，16k 单声道 mp3，≤60s | **2026-11-14 实测通过**（大模型听写在本 APPID 下 `11201 licc failed`，未开通） |
| 2.2 评价 | **内容正确度**：ASR 转写文本比对 + Spark X2.6 语义判分，**不接 ISE、不给发音分** | 用户已定 |
| 2.3 中文判分 | 听写转写 + 关键词覆盖，Spark X2.6 兜底语义相似度 | 可用 |
| 输入框作答 | 跳过 ASR，直接做文本比对 / 语义判分 | 可用 |

**拍照链路（已确定为两段式）**

```
拍照 → 图片压缩(≤4M base64) → OCR大模型 se75ocrbm（App 端签名、直连）
     → payload.result.text 是 base64，解码后是一个含 document[] + image[] 的 JSON
     → 只取 document[].value（markdown），丢掉版面坐标
     → Spark X2.6 抽取词条 JSON（**忽略并重新生成音标**）→ 人工校对页 → 本地入库
```

`spark-x2.6` 是纯文本推理模型，**不支持图片输入**，所以 OCR 必须走独立接口。OCR 与听写、合成共用同一组 APPID / APIKey / APISecret 签名三元组。

**文本导入有两条路（2026-11-14 新增 AI 选项）**

| 模式 | 流程 |
|---|---|
| 默认（本地） | 粘贴文本 → 本地按行解析（`services/parser-text`）→ 校对页逐条确认 → 入库 |
| 开「AI 整理并分单元入库」 | 粘贴整本书文本 → 本地按 `Unit N` / `Starter Unit N` / `第 N 单元` 标题切段（每段 ≤3500 字，`parser.splitUnitSections`）→ 逐段交 X2.6 抽取（音标仍按单词重生成）→ **同名单元追加、重复词跳过 → 直接入库**，完成后弹汇总并回首页 |

AI 路线不做逐条校对，因此切段与清洗必须是纯函数、可离线自测（`tests/parser-unit.test.ts`）；云的建 WSS / HTTPS 能力在 H5 预览不可用，开关仅 App 内生效。校对页的单元名现在**可直接输入修改**，已有单元也可在同一个选择器里「改名」（`library.renameUnit`）。

**2026-11-06 已联调**：两种签名 host 都返回 `code=0`，401 疑虑排除；一张三行单词表实测中英文单词与中文释义全对、词性轻微污染、**IPA 音标 3/3 损坏**，改由模型按单词重生成后 3/3 正确。完整实测记录见 `讯飞接口配置.md` 第 8 节——这是 P2 抽取 prompt 与校对页设计的直接依据。

### 关于安卓原生能力（已核实结论）

- **TTS 原生可用**：`plus.android.importClass('android.speech.tts.TextToSpeech')` + `plus.android.implements('...TextToSpeech$OnInitListener')`，`setLanguage` / `setSpeechRate` / `speak` 即可，完全离线、免费。风险是中文语音包可能 `LANG_MISSING_DATA`。
- **ASR 原生不可作为唯一依赖**：国内无 GMS 的 ROM 上 `SpeechRecognizer.isRecognitionAvailable()` 常返回 false；即便探测到 OEM 引擎，也只返回纯文本、弹系统 UI、无音素与置信度，做不了发音评分。
- 第一版既然已选定讯飞，原生 TTS / ASR 就作为**无网降级档**保留在能力层接口后面，不进主线。

### 三档配置（保留扩展性）

| 档位 | TTS | ASR | 2.2 评价 | 成本 |
|---|---|---|---|---|
| A 纯原生（无网降级） | 系统 TTS | 系统 SpeechRecognizer + OEM 探测，失败转输入框 | 仅文本准确率 | 0 |
| **B 讯飞（第一版，已定）** | 超拟人合成 | 语音听写（经典流式版）V2.0 | **内容正确度**，不接 ISE | 按量 |
| C 全能力（日后可选） | 同 B | 同 B | 补讯飞语音评测 ISE，升级为发音评分 | 按量，更高 |

用户已选 B 档的「内容正确度」口径；C 档仅是能力层预留的升级路径，不在第一版范围。

## 8. 安全与架构红线（方案 C）

1. **源码仓库不含密钥**：MaaS `ak-` Key 与私有接口三元组只从本地 `.env.local`（已 gitignore）在构建期注入，代码里只出现环境变量名。密钥**只存在于产物 APK** —— 这是用户 2026-11-06 明确授权的例外（「这是我自己学习用的 app，场景选 C」）。
2. **补偿措施，缺一不可**：密钥分片 + 运行时拼接或放 native 层，禁止明文整串；构建开启代码混淆、打包后做一次免费加固；讯飞控制台设用量上限与告警；APK 只装自己手机、不外传不上架；异常用量立即轮换。
3. 日志禁止打印密钥、签名串、完整鉴权 URL（含查询参数）、请求体中的 `app_id` 与图片 base64 —— **App 运行时同样禁止**。
4. 讯飞返回的合成音频、识别文本按最小必要缓存，遵守隐私政策说明（相机、麦克风、第三方 AI 服务）。
5. 签名依赖 GMT RFC1123 时间，容差 ±300s；**手机系统时间不准会 401**，要检测并提示校准，且不要缓存签名 URL（现用现签）。
6. **无代理层**：App 端 `uni.request` / `uni.connectSocket` 直连讯飞，不依赖电脑 / 服务器 / 云函数。OCR 文档里「不支持跨域、不适用于浏览器」只约束 H5；App 端走原生网络栈，不受 CORS 限制。
7. **分发即迁移**：一旦要给别人用、多人使用或上架，必须先切到云函数方案（第 11 节 B），不得沿用 C 发布。

## 11. 独立运行方案 C（已定，2026-11-06）

### 11.1 授权与结论

用户明确：「**这是我自己学习用的 app，场景选 C**」，即接受「APK 可被反编译、密钥可能被提取」的风险。

**结论：APK 完全独立运行。** 不需要电脑常开、不需要服务器、不需要云账号、不需要同一 WiFi。手机装好、联网即可使用全部功能；断网时首页、词条与已缓存音频仍可用。

`AGENTS.md` 第 4 节据此对「签名必须服务端完成」开了**自用例外**，同时把补偿措施列为必做项；该授权**仅限自用**，一旦要分发 / 上架 / 多人使用，必须先迁到 11.5 的 B 方案。

### 11.2 为什么可行（技术核查）

- 之前写的「OCR 不支持跨域、不适用于浏览器 → 必须代理」，**这条只约束 H5 / 浏览器**。uni-app **App 端 `uni.request` 走原生网络栈，没有同源策略，不受 CORS 限制**；`uni.connectSocket` 直连 WSS 同理。
- HMAC-SHA256 签名只是标准算法（`host / date / request-line` + APIKey + APISecret），不依赖任何服务端能力。`tools/proxy.py` 的 `auth_query()` 已实测能签出有效 URL（四个接口鉴权全通过），把它翻译成 App 端 TypeScript 即可，逻辑等价。
- 因此**「开电脑」从来不是技术必需**，只是「把密钥放在电脑上」那个方案的副作用。C 方案下这层依赖整个消失。

### 11.3 工程落地（P1 一并做）

| 项 | 做法 |
|---|---|
| 签名模块 | `src/api/xfyun-sign.ts`：GMT RFC1123 `date` → HMAC-SHA256 → base64 → `authorization` → 拼 URL。WSS 请求行用 `GET`，OCR 用 `POST`；**现用现签，不缓存签名 URL** |
| 依赖 | 轻量 crypto（`@noble/hashes` / `crypto-js`）+ base64；**不引原生插件、不需要自定义基座**，云打包即可 |
| 密钥注入 | 构建期从 `.env.local` 经 Vite 注入；源码仓库只有键名。运行时由分片常量拼接，避免整串明文 |
| 网络 | `uni.request`（MaaS / OCR）、`uni.connectSocket`（听写 / 合成）；超时 OCR 30s、MaaS 90s；统一 429 退避重试 |
| 设备时间 | 启动或首次 401 时检测本机与 GMT 偏差，>120s 提示校准（服务端容差 ±300s） |
| 日志 | 统一请求拦截器脱敏，禁止输出 `Authorization`、签名串、完整鉴权 URL、`app_id`、图片 base64 |
| 打包 | 开启代码混淆；产出 APK 后做一次免费加固；讯飞控制台设用量上限与告警 |

### 11.4 风险与补偿措施（必须全做）

| 风险 | 措施 |
|---|---|
| 反编译直接读到密钥明文 | 分片拼接 / native 层存放 + 代码混淆 + 免费加固 |
| 密钥被盗刷产生费用 | 控制台**用量上限 + 告警**；异常立即轮换（只改 `.env.local` 重新打包） |
| 日志 / 崩溃上报泄露 | 日志脱敏；不接第三方崩溃收集 |
| APK 落到别人手里 | **只装自己手机，不外传、不上架、不分发** |
| 手机时间不准导致 401 | 11.3 的时间偏差检测与提示 |
| 无网络 | 本地 SQLite + 音频缓存；2.3 可用输入框作答，默写用本地键盘照常作答 |

> **关键边界：密钥进 APK ≠ 密钥进代码仓库。** 仓库里依然一个真实值都没有，泄露仓库不等于泄露密钥；只有 APK 落到别人手里才触发风险。这条边界必须守住，`AGENTS.md` 第 4 节第 1、3 条不因 C 而放宽。

### 11.5 未采用的方案（保留作迁移路径）

- **A 本机代理**：`tools/proxy.py` 已实现并自测，仅用于 P0 联调复现签名，**正式 APK 不使用**。

### 13.2 链路与边界

1. 「手工添加短文」页（`pages/read/compose`）收名称 + 正文；提交时先用 `markdownToSentences()` 本地切句（去中文注解 / 页码 / 断词，最多 60 句），**再联网调用 `services/passage-translate.translateSentences()` 让 X2.6 整句翻译成中文**（15 句一批、`thinking: disabled`、60s 超时；模型漏项时自动重试一批）。翻译失败或断网时**照常保存英文**，译文为空，学习页可补。
2. 名称留空时用 `fallbackTitle()` 取第一句前 6 个词；入库写 `read_article`（`content` = 句子 JSON，`translations` = 等长译文 JSON；老库由 `initDatabase()` 补列，缺列按空译文读回），保存后 `navigateBack()` 回到跟读列表（新文章排最前），由用户点开开始跟读。
3. 学习页打开没有译文的文章（老数据 / 添加时断网）会**自动补一次** `translateSentences()`，成功后用 `storage.updateArticleTranslations()` 写回 `read_article.translations`；失败则在标题卡显示「生成翻译」按钮供手动重试（离线时提示稍后再试）。
3. 能力层的 `services.recognize()` / `extractPassage()`（OCR + X2.6 整理）保留但当前 UI 不暴露；若以后恢复拍照入口，仍复用同一套入库逻辑。
4. 学习页复用 `services/player` 队列：整段 = 每句一个片段，`onSegStart` 高亮当前句；单句与单词各自成段；录音一开始就 `stop()` 当前播放。
5. `services.evaluatePassage()`：先本地逐词对齐（加权 LCS，完全读对 1 分、同音 / 一个字母误差 0.85 分、漏读 0 分，多读轻扣 3%/词、最多 15%）；只有本地分处于 1–99 的模糊区间才调用 X2.6 语义兜底，云失败静默保留本地分。
6. 逐句得分写 `read_record`；学习页按句取最近一次分数显示「已练」，整篇均分 = 已练句子分数的平均。
7. 跟读文章**不进**词库备份 bundle（`version: 1` 只覆盖 unit / word）；与练习记录一样只留在本机，清空词库不影响跟读数据。
8. 点词释义走 `services/dictionary.lookupGlosses()`（2026-11-21 由 `lookupWordBrief` 升级而来）：按「我的词库精确命中（离线）→ `gloss_cache` 查过的速览（离线）→ 一次批量速览请求 X2.6（联网）」三级回退，**只取单词 / 音标 / 中文释义**，不写 `dict_history`，也不写完整词典的 `dict_cache`（简版条目不会污染「词典」页）。音标按设置里的英美口音选择，缺一退回另一套。
   - **提速**：速览 prompt 只要 30 字内的释义 + 音标，`max_tokens` 900、超时 20s（完整词条要例句 / 搭配 / 同义词，输出大一个量级）；一行可查最多 10 个词，实测 spark-x2.6 单次仍约 4s，瓶颈是模型的固定首响，不是输出长度。
   - **预热**：学习页在打开文章和每次切句时，把「当前句 + 下一句」尚未缓存的单词合并成**一次**请求预热；点词时通常已命中本地，实测点词到出释义 <100ms。查过的速览永久缓存，断网可复看。
9. 单词连读：长按词进入 `phraseMode`（`longpress` 后 400ms 内压掉浏览器补发的 click，避免「选中即取消」）；选中词按 `(句号, 词号)` 排序，用空格拼成一段文本交给 `playQueue` 的**单个片段**，TTS 一次合成，连读 / 弱读 / 变音由模型处理；音频走同一套 TTS 缓存（键 = 拼接文本），重复连读零请求。切句 / 整段朗读 / 返回会退出选择；「取消」清空但不影响单词释义。

## 14. 朗读音频缓存（2026-11-21 新增）

为省合成调用费用加的本地缓存；**不是**新页面、不是新练习模式，播放链路与状态机不变。

### 14.1 口径

| 项 | 口径 |
|---|---|
| 缓存什么 | 合成成功的每一条朗读音频（单词、中文释义、跟读句子、词典例句都走同一条链路） |
| 键 | `sha256(归一化文本 : 语言 : 发音人 : 语速)` 前 10 字节，文件名 `_doc/audio/<hash>.mp3` |
| 命中 | 直接播本地文件，**不发请求、不计费**；断网时已缓存内容照常可播 |
| 未命中 | 走讯飞超拟人合成，成功即落盘 + 写 `media_cache` 索引 |
| 生命周期 | 永不过期，按总容量 **300 MB** LRU 淘汰（删到上限的 80%），行与 mp3 一起删 |
| 音量 | **不参与缓存键**：云端固定 100 合成，音量在播放器侧施加，任何音量共用一份音频 |
| 入口 | 设置页「朗读缓存」卡片：条数 / 占用 / 本次命中率 / 一键清理 |

### 14.2 实现要点

1. 归一化只折叠空白（全角空格、换行、连续空格）与 Unicode NFC，**不动标点**：标点影响停顿与语调。键结构与历史版本一致，干净文本的老缓存仍然命中。
2. 命中前用 `probeFile()` 校验文件真实存在且非空；索引在、文件没了（用户清过存储 / 写入中断 / 老库 30 天过期）一律按未命中处理，并当场删掉死索引 —— 下次播放自动重新合成，不会永久降级原生 TTS。
3. 命中回写 `hits + 1` / `last_used_at`，同一 key 60 秒内不重复写库；老库行 `bytes = 0` 时借首次命中回填。
4. `expired_at = 0` 表示永不过期；老库遗留的按天过期行**文件还在就直接复活**（清 TTL，不重新合成），只有文件缺失或 0 字节才删索引重合成。
5. 已装的旧库没有 `bytes / hits / last_used_at`，`initDatabase()` 用 `PRAGMA table_info` + `ALTER TABLE ADD COLUMN` 补列（只加列，不改列）。
6. 超过 300 MB 时 `pickEvictions()` 按 `last_used_at` 升序淘汰到 80%；容量检查每合成后触发但每分钟最多统计一次，老库 `bytes = 0` 的行不会把淘汰卡在某一轮。
7. 启动时扫一次 `_doc/audio` 孤儿 mp3（写文件成功但写索引失败留下的），只删没有索引的；播放中不扫，避免误删正在写的文件。
8. 索引写失败不阻塞播放：音频已在本地，本次先播，代价只是下次再合成一次。
9. 音量不再发给云端后，`dedupe()` 的并发合并键也去掉了音量，同一句在不同音量下并发只合成一次。

### 14.3 验收

1. 同一单词连续播放两次：第二次日志出现 `tts.cache.hit`，控制台无新的合成请求；把 `_doc/audio` 里对应 mp3 删掉后再播，能自动重新合成并恢复命中。
2. 改音量后播放同一句：不再产生新的合成请求，音量正确（不是衰减两次）。
3. 设置页显示条数 / 占用 / 本次命中率；点「清理朗读缓存」后条数归零，目录内 mp3 清空，词库与练习记录不受影响。
4. 累计音频超过 300 MB 时自动淘汰最久未播放的条目，总量回落到 80% 以下。
5. `tests/tts-cache.test.ts` 覆盖归一化、键稳定性、LRU 淘汰集合、死条目自愈、命中回写、清理与孤儿清扫；`npm test`、`vue-tsc`、`build:app` / `build:h5` 全过。

## 15. 「我的」页与错词本明细（2026-11-21 新增）

底部导航固定 4 项：**首页 / 词库 / 跟读 / 我的**（2026-11-22 起移除「词典」tab，词典改从首页快捷入口进入；原「设置」tab 已收进「我的」）。

### 15.1 「我的」页

| 菜单 | 行为 |
|---|---|
| 学习记录 | 打开 `pages/records/records`：按天分组的每次学习会话（时长 / 作答次数 / 平均分 / 达标次数），顶部汇总今日与近 7 天时长 |
| 设置 | `navigateTo` 打开原设置页（语速、发音、推进、朗读缓存等） |
| 关于 | 打开 `pages/about/about`：版本、功能清单、数据与隐私说明、评分口径 |
| 退出 | 二次确认后 `plus.runtime.quit()`（仅 App 端）；H5 预览提示无法退出 |

### 15.1.1 学习记录的设计

- **一条记录 = 一次学习会话**，不按每道题记（明细仍在 `practice_record` / `read_record`），避免记录表膨胀。
- 写入 `study_session`：`kind`（practice / read）、`mode`（2.1 / 2.2 / 2.3 / dictation / read）、`unit_id`、`title`、`started_at` / `ended_at` / `duration_sec`、`total`（词数 / 句数）、`answered`（作答次数，含「取消」跳过）、`passed`（≥ 60 分次数）、`avg_score`。
- **何时落库**：练习页在 `onHide / onUnload / onBackPress / 最后一题完成` 时写一次（`sessionSaved` 防重复）；跟读页在离开时写一次。**不足 10 秒且没有作答**的误触不记录。
- **切后台**：`onShow` 回来时若上一段已落库，则重新计时，避免一次记录跨几个小时。
- **不统计**：词典查词、首页浏览、无作答且不足 10 秒的停留。
- 汇总口径：今日 / 近 7 天按 `started_at` 落在区间内的 `duration_sec` 求和；列表最多读最近 200 条，支持一键清空（只删记录，不动词库与成绩明细）。

### 15.2 错词本明细

1. 每次作答（2.2 / 2.3 / 默写）都会写 `practice_record`；2.1 共读不作答、不产生成绩记录；默写额外在 `detail_json` 里记 `dictation: true`，便于区分作答方式。
2. 低于「错词阈值」的作答沿用原逻辑：`word.wrong = 1`、`wrong_count + 1`；「已掌握」仍写 `input_type = 'mastered'` 并清零。
3. 错词本每个词显示最近一次成绩摘要（分数 / 方式 / 时间），点开看最近 6 次：方式（默写 / 中英·语音 / 中英·输入 / 英中·语音 / 英中·输入 / 共读）、分数、你的作答、标准答案、时间。
4. 错词本列表改为**多选**：每个词左侧圆圈勾选，支持「全选 / 取消全选」，顶部只保留导出 / 导入；「默写重练 / 语音重练」固定在页底操作条，未勾选时置灰。重练把勾选词的 `wordIds` 传给练习页（`mode=2.2[&input=type]`），练习页在加载后用 `wordIds` 精确过滤，**只练选中的错词**，不再拉整单元。

### 15.3 验收

1. 默写答错后进入错词本，能看到该词「错 N 次」、最近一次分数与「默写」标记；展开能看到刚才写的答案与标准答案。
2. 「默写重练 / 语音重练」在页底固定条：先勾选单词（或全选），按钮才可用；练习页只加载勾选的词（计数 = 勾选数），默写为自定义 26 键、语音为 2.2。
3. 「我的」四个菜单（学习记录 / 设置 / 关于 / 退出）都能进入对应页面；App 端「退出」能关闭应用，H5 给出提示。
4. 完成一轮练习（或跟读停留 ≥10 秒）后进入「我的 → 学习记录」：能看到该次会话的时长、作答次数、平均分与达标次数，按天分组；今日 / 近 7 天汇总随记录更新；清空记录后列表为空，词库与成绩明细不受影响。

## 16. 云端后端（2026-11-23 新增）

> 本节记录「数据上云」的新方向；**App 端尚未接入**，当前 APK 仍按第 11 节方案 C 直连讯飞。下一轮改造 App 的登录、同步与 AI base URL。

- 工程：`admin/`，Laravel 12 + Vue 3.5 + Element Plus，单站点提供 `/admin`、`/api/admin`、`/api/v1`。
- 账号：后台管理员 `users` 与 App 用户 `app_users` 分表、分 guard；App 多账号、数据按 `app_user_id` 隔离。
- 同步：本地 SQLite 仍是主库；登录后按 `sync_seq` 增量 push / pull。业务表带 `uuid`、`client_updated_at_ms`、`sync_seq`、软删除墓碑；冲突按最后写入胜。
- 同步范围：unit / word / practice_record / read_article / read_record / study_session / app_settings；词典缓存、点词速览、本地音频不入云。
- AI：OCR、词条抽取、判分、词典、TTS、ASR、逐句翻译/跟读全部由后端代理讯飞，APK 不再携带密钥；服务端按文本缓存 TTS 音频。
- 后台：工作台、App 用户、词库、跟读、练习记录、学习统计、AI 用量、系统管理（管理员 / 角色 / 权限菜单 / 日志 / 配置）。
- 部署：宝塔单站点，MySQL 8，缓存/队列默认数据库；步骤见 `admin/docs/部署-宝塔.md`。
- 契约：`admin/docs/API.md`。
- 设计 / 计划：`docs/plans/2026-11-22-cloud-backend-design.md`、`docs/plans/2026-11-22-cloud-backend.md`。

**App 接入下一轮要做的**：

1. 登录页 / token 存储（`uni.setStorage`），token 失效回登录；设备 id 持久化。
