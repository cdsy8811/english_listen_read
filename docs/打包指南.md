## 1. 为什么最后一步必须由你在 HBuilderX 完成

- 本机没有 Android SDK / Gradle 环境，无法离线打包 APK。
- 本机已装 HBuilderX 4.87（`D:\HBuilderX`）。其 CLI 只有 `publish app-android --type appResource`（生成**本地打包 App 资源**）和鸿蒙本地打包，**没有 Android 云打包命令**（`cli.exe pack --help` 可查）。
- 云打包需要 **DCloud 账号登录态 + 云端证书 + 云端构建队列**，命令行不能代替登录，因此这一步无法由脚本代劳。
- 这不影响「APK 完全独立运行」：装好后不需要电脑、服务器、云账号或同一 WiFi，手机联网即可直连讯飞。

### 7.1 关于 H5 浏览器预览（`dev:h5` / `build:h5`）

浏览器有同源策略，讯飞接口不返回 `Access-Control-Allow-Origin`，所以**浏览器无法直连讯飞**；这不是代码 bug，也不影响 APK —— App 端 `uni.request` / `uni.connectSocket` 走原生网络栈，不受 CORS 约束（方案 C 的网络约定）。

2026-11-07 起，`npm run dev:h5` 增加了一个**只在本机存在的开发代理**（`vite.config.ts` 的 `devCloudProxyPlugin`，仅在 `configureServer` 阶段注册，`build` 时完全不进产物）：

| 能力 | H5 预览（dev） | App 真机 / APK |
|---|---|---|
| 词库、单元、设置、错词本、导入导出 | 可用（内存降级库） | 可用（`plus.sqlite`） |
| 拍照 OCR → X2.6 抽取 | **可用**：浏览器只请求同源 `/__dev/xfyun/ocr`、`/__dev/xfyun/chat`，由 dev server 用 `.env.local` 的凭据签名后转发 | 直连讯飞（自签名） |
| 输入框作答 + 内容正确度评分 | 可用（纯本地文本比对） | 可用（本地 + X2.6 语义兜底） |
| 超拟人合成（朗读） | **可用**：浏览器请求同源 `/__dev/xfyun/tts`，dev server 用 `.env.local` 的凭据签名建 WSS、逐帧解码后回 mp3 | 客户端自己签名直连 WSS |
| 录音听写 | 不可用（需真机）：提示「浏览器预览不支持语音服务」，作答改输入框 | 直连讯飞 WSS |
| 密钥 | 浏览器包里**没有**任何分片；代理只在 Node 进程内使用真实值 | 分片注入，运行时还原 |

所以「浏览器里识别一直失败」的两种情况要分清：
1. **报 `云能力未就绪` / `浏览器预览不支持直连讯飞`** —— 用 `npm run dev:h5` 启动，并确认 `E:\英语\.env.local` 存在（`npm run prepare:env` 可生成），刷新页面即可；dev server 控制台会打印 `[dev-proxy] ocr → 200`。
2. **报 `模型未返回内容` 或 `词条抽取失败`** —— 已修复：X2.6 的思考过程（`reasoning_content`）会占用 `max_tokens`，额度小就会返回空 `content`（`finish_reason=length`）。现在抽取/判分固定传 `thinking: { type: 'disabled' }` 且抽取额度 4096，实测同一张单词表 **OCR 1.8s + 抽取 10.9s** 稳定出 17 条。

改动落在 `src/utils/clock.ts`、`src/api/http.ts`（H5 不发 WSS，错误码 `-1` 不重试也不刷错误日志）、`src/services/index.ts`（H5 评价只走本地）、`src/api/xfyun-maas.ts`（`buildChatBody` + 关闭思考）、`vite.config.ts`（`h5CredentialGuardPlugin` + `devCloudProxyPlugin`）。

随时可复验：
- `npm run build:h5 && npm run verify:h5`（H5 产物明文 0、分片片段 ≤3 偶合、无讯飞地址、**不含 `/__dev/xfyun` 路径**）；
- `node scripts/verify-h5-clean.mjs dist/build/app` 是**阳性对照**，应判定失败（App 产物 19/19 分片命中），证明检查脚本确实有效；
- `npm run probe:ocr -- <图片路径>`：不经 App 也能跑通「OCR → 抽取 → 清洗」，排查识别问题最快。

> 改完配置后 Vite 会自动重启 dev server，**刷新一次浏览器页面**即可。录音听写仍需 APK 或自定义基座验证。

- 合帧必须**逐帧解码再拼接字节**：单帧 base64 自带 `=` 补位，字符串直接拼接会在第一个补位处截断（表现为一句话只播出第一帧，实测 3836 字节 vs 完整 17496 字节）。

## 7.2 内置「初一词汇」：教材词汇表数据链（2026-11-08）

首页的「载入初一词汇」按钮写入的是**教材真实词表**，不是人工整理词表。数据来源与加工链：

1. `FreePEP`（`https://github.com/siknet/FreePEP`）给出教材目录与官方 `book_id`；用户用其 Windows 发行包把
   《义务教育教科书 英语 七年级上册 / 下册》PDF 下载到本机（教材版权归人民教育出版社，仅个人学习用，不打包进 APK、不分发）。
2. `tools/pep/extract_pdf_jpegs.py` 从图片型 PDF 直接抽出每页内嵌 JPEG（七上 140 页、七下 132 页），不依赖第三方库。
3. 人工核对页码范围：七上 `Vocabulary in Each Unit` 在 PDF 116–122 页，七下在 107–115 页；
   其后的 `Vocabulary A-Z` / `Vocabulary from Primary School` / `Reference Word List` 是重复或小学词汇，不收录。
4. `scripts/ocr-page.ts`：讯飞通用文档识别单页 OCR → markdown（逐页结果缓存在 `tools/pep/md/`）。
5. `scripts/extract-pep-vocab.ts`：X2.6 逐页结构化抽取（关闭思考、忽略 OCR 音标并按单词重生成 IPA、输出印刷页码 `p.XX`）。
   卡在 WAF 或整页 OCR 丢栏时，把该页切成左右两半分别 OCR 再合并，实测可找回整栏词条。
6. `scripts/build-pep-vocab.mjs`：按目录里的单元起始页（七上 1/7/13/19/27/35/43/51/59/67，七下 1/9/17/25/33/41/49/57）
   把词条归到单元；清洗词性、释义、去重，产出 `src/data/vocab-pep7.ts`（随 APK 打包）与
   `data/人教版七上七下_教材词汇表.json`（可走首页「导入」粘贴）。

最终 **18 个单元 / 785 条词条**（含短语与专有名词；短语无音标）。音标是模型重新生成的标准英式 IPA，
个别词条与印本若有一两个字差异，首页「编辑」可改。重新生成：`node scripts/build-pep-vocab.mjs`（前提：逐页抽取结果仍在 `tools/pep/extracted/`）。
