# 宝塔面板部署指南

目标：在一台 Linux 云服务器上，用宝塔面板部署 `admin/`，同时提供
`https://你的域名/admin` 与 `https://你的域名/api/v1`。

## 1. 环境要求

- Linux（CentOS / Ubuntu / Debian 均可），宝塔面板 8+
- Nginx 1.20+
- PHP 8.2 / 8.3（推荐 8.3），扩展：
  `fileinfo`、`mbstring`、`openssl`、`pdo_mysql`、`curl`、`zip`、`bcmath`、`gd`
- MySQL 8.0，字符集 `utf8mb4`
- Node.js 20+（仅构建前端用，构建完可卸载）
- Composer 2
- 可选 Redis 7（不装也能跑，缓存/队列默认数据库）

## 2. 建站与上传

1. 宝塔「网站」→「添加站点」：
   - 域名：`admin.example.com`（换成你的）
   - PHP 版本：8.3
   - 数据库：MySQL，创建库 `orange_english`，字符集 `utf8mb4`
2. 把仓库的 `admin/` 目录上传到服务器，例如 `/www/wwwroot/orange-english/admin`。
3. 站点根目录设置为 `/www/wwwroot/orange-english/admin/public`。
4. 申请并开启 SSL（Let's Encrypt），开启「强制 HTTPS」。

## 3. 安装依赖

SSH 进入项目目录：

```bash
cd /www/wwwroot/orange-english/admin
composer install --no-dev --optimize-autoloader
cp .env.example .env
php artisan key:generate
```

编辑 `.env`：

```dotenv
APP_NAME="橙子英语"
APP_ENV=production
APP_DEBUG=false
APP_URL=https://admin.example.com

DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=orange_english
DB_USERNAME=orange_english
DB_PASSWORD=换成强密码

CACHE_STORE=database
QUEUE_CONNECTION=database
SESSION_DRIVER=file

# 讯飞（只写在服务器，不要提交）

XFYUN_API_KEY=
XFYUN_API_SECRET=
XFYUN_MAAS_API_KEY=
XFYUN_MAAS_BASE_URL=https://maas-api.cn-huabei-1.xf-yun.com/v2
XFYUN_MAAS_MODEL=spark-x2.6

XFYUN_OCR_SIGN_HOST=cbm01.cn-huabei-1.xf-yun.com
```

> `.env`。仓库里永远只保留键名。

## 4. 初始化数据库与管理员

```bash
php artisan migrate --force
php artisan db:seed --force
php artisan app:create-admin --password='换成至少8位强密码'
```

`app:create-admin` 会创建/重置 `admin` 账号并绑定超级管理员角色。
生产环境不要把密码写进 shell 历史，可用交互模式：

```bash
php artisan app:create-admin
```

## 5. 构建前端

```bash
npm ci
npm run build
```

构建产物在 `public/build`，由 Nginx 直接托管，不需要常驻 Node。

## 6. 目录权限

```bash
chown -R www:www storage bootstrap/cache
chmod -R 775 storage bootstrap/cache
```

（宝塔的 PHP-FPM 用户通常是 `www`，以实际为准。）

## 7. Nginx 配置

宝塔站点「设置」→「配置文件」，确认站点根目录与伪静态：

```nginx
root /www/wwwroot/orange-english/admin/public;
index index.php index.html;

location / {
    try_files $uri $uri/ /index.php?$query_string;
}

location ~ \.php$ {
    include fastcgi_params;
    fastcgi_pass unix:/tmp/php-cgi-83.sock; # 以宝塔实际 sock 为准
    fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
    fastcgi_read_timeout 120s;
}

client_max_body_size 8m;

location ~ /\.(env|git) {
    deny all;
}

location ~ ^/(storage|vendor)/ {
    deny all;
}
```

在宝塔「PHP 设置」里把 `max_execution_time` 调到 120 秒，
`upload_max_filesize` / `post_max_size` 调到 8M 以上（OCR/ASR 需要）。

## 8. 定时任务

宝塔「计划任务」→ 添加 Shell 脚本，每分钟执行：

```bash
cd /www/wwwroot/orange-english/admin && php artisan schedule:run >> /dev/null 2>&1
```

已内置：

- `app:prune-tts` 每天 03:10 按容量上限清理音频缓存
- `app:prune-tombstones` 每天 03:20 清理 180 天前同步墓碑
- `app:prune-logs` 每周一 03:30 清理 90 天前日志

## 9. 队列（可选）

AI 请求目前同步处理，队列只用于后续导出/清理任务。若需要：

```bash
php artisan queue:work --sleep=3 --tries=3 --timeout=120
```

用宝塔「进程守护管理器」常驻，或 `supervisor`。不启动也不影响主流程。

## 10. 首次验收

1. 浏览器打开 `https://admin.example.com/admin`，用 `admin` 登录。
2. 工作台能看到统计；「App 用户」创建 `demo` 账号。
3. 用 curl 跑 App 登录与同步：

```bash
curl -X POST https://admin.example.com/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"demo","password":"demo123456","device_id":"server-test"}'
```

4. 拿 token 拉同步：

```bash
curl 'https://admin.example.com/api/v1/sync/pull?cursor=0' \
  -H 'Authorization: Bearer 1|xxxx'
```

5. 后台「系统配置」填好 AI 配额，再在 App 端联调 OCR/TTS/ASR。

## 11. 安全清单

- [ ] `.env` 不在 Web 根目录可访问（已在 Nginx 拒绝）。
- [ ] `APP_DEBUG=false`，`APP_ENV=production`。
- [ ] 数据库只监听 127.0.0.1，或仅内网。
- [ ] 宝塔面板改端口 + 强密码 + 绑定 IP / 开启二次验证。
- [ ] 讯飞控制台设置用量上限与告警。
- [ ] 定期备份 MySQL 与 `storage/app/private/tts`。
- [ ] 不在聊天/日志/提交里出现真实密钥。
- [ ] `admin` 初始密码登录后立即修改。

## 12. 常见问题

**500 / 白屏**
看 `storage/logs/laravel.log`；确认 `storage`、`bootstrap/cache` 可写，
`php artisan key:generate` 已执行。

**`/admin` 404**
站点根目录必须指向 `admin/public`，并配置 `try_files`。

**上传 OCR 报 413**
调大 Nginx `client_max_body_size` 与 PHP `post_max_size`。

**AI 报「凭据未配置」**
`.env` 的 `XFYUN_*` 未填或改了没执行
`php artisan config:clear`。

**Scheduler 不跑**
计划任务里的路径必须是绝对路径；先手动执行
`php artisan schedule:run` 看输出。

**同步冲突多**
确认 App 端每次修改都更新 `client_updated_at_ms`；设备时间偏差超过 24h 会被判
`invalid`。
